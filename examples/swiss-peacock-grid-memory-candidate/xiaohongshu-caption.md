# 小红书标题

智能体是怎么记事的？

# 正文

ByteByteGo 这篇把 AI 智能体的“记忆”讲得很清楚：模型本身其实没有持续状态。每一次调用，它看到的只是当前上下文窗口里的内容。我们在 ChatGPT、Claude 里感受到的连续性，来自产品系统在背后替模型保存、检索、摘要，再把相关信息重新放回 prompt。

这个区别很重要。很多人说“AI 记住我了”，但更准确的说法是：产品在模型外面建了一套记忆系统，让模型每一轮都能看到它此刻该看的东西。模型负责推理，系统负责把材料摆到它眼前。

最直觉的做法，是把所有历史对话都塞进上下文窗口。刚开始有效，聊久了就会出问题：token 成本变高，响应变慢，长上下文中间的信息也更容易被忽略。更大的窗口只是扩大空间，不代表模型真的会稳定想起所有细节。

所以真实的 Agent 记忆，一般会分层。最上面是上下文窗口，快、贵、容量小；下面是会话记忆，保存最近活动；再往下是长期存储，放用户事实、偏好和摘要；最底层是冷归档，访问少，但能留作审计或以后参考。相关信息需要时被提升进窗口，不相关时就沉到更便宜的存储层。

同时，AI 要记的也不是一种东西。当前任务里的代码和最近消息，是工作记忆；几天前讨论过某个清单，是情景记忆；“这个用户偏好 Python”这种稳定事实，是语义记忆；“他喜欢三段式状态更新”这种做事方式，则更像程序性记忆。不同智能体需要的混合比例也不一样，客服、编程、个人助理，不该用同一套记忆设计。

真正难的地方，其实不是“存下来”。把内容写进数据库或向量库，工程上已经有很多成熟工具。难的是每一轮用户发消息时，系统要判断哪些旧信息此刻相关，哪些只是噪音。取错旧信息，比完全没有记忆更麻烦。没记忆时模型至少知道自己只看当前输入；取错记忆时，它会把过期或不相关的信息当成事实继续推理。

这也是 memory 功能最容易被低估的风险。旧偏好可能过期，摘要会抹掉名字、日期、承诺这类细节，长期记忆也可能被污染。记忆越有用，越要有更新、衰减、验证和清理机制。

所以以后看到一个 AI 产品说自己支持 memory，我觉得更好的问题不是“模型能不能记住我”，而是：它存了什么？什么时候取？旧事实怎么更新？错误记忆怎么清理？

你觉得现在的 AI 工具里，最难解决的是“忘事”，还是“记住了错误的事”？
