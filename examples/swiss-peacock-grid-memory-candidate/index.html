MODEL CONTRACT

模型每次都从
空白开始

你感受到的连续性，不是模型自己记住了，而是平台在每次调用前重新摆好上下文。

CALL 01

Prompt

MODEL

Run once

模型只处理这一轮窗口里的文本。

NEXT CALL

Blank again

下一次调用，本身没有上一轮状态。

“Claude 记得我”是产品属性，不是模型属性。
平台替模型保存、检索、摘要，再把相关内容塞回 prompt。

03 · Context Window「两克伴」出品

CONTEXT IS NOT MEMORY

上下文窗口
不是记忆

把历史全塞进去，短期有用；对话一长，成本、延迟和中间迷失会一起出现。

窗口再大，也不等于记忆可靠。
模型能看到窗口内文本，但长上下文中间的信息仍可能被忽略。
Cost · Latency · Lost in the MiddleContext
04 · Hierarchy「两克伴」出品

MEMORY SYSTEM

记忆系统
要分层

真实生产系统会在速度、容量和成本之间分层管理信息。

相关时提升进窗口，不相关时沉到存储层。
这更像操作系统内存分页，而不是模型脑子里多了一块记忆。

05 · Memory Types「两克伴」出品

FOUR TYPES

AI 要记的
不是一种东西

记忆层级回答“存在哪里”，记忆类型回答“这条信息是什么”。

WORKING

工作记忆

当前任务现场：代码、文件、最近几句话。

EPISODIC

情景记忆

某次具体互动：什么时候讨论过什么。

SEMANTIC

语义记忆

稳定事实和偏好：你常用什么工具。

PROCEDURAL

程序性记忆

做事方式：你希望它按什么格式工作。

正确的混合是设计选择，不是固定公式。
客服智能体偏情景和语义；编码智能体更依赖程序性记忆。
Working · Episodic · Semantic · ProceduralTypes
06 · Retrieval「两克伴」出品

REAL HARD PART

难点不是存，
而是取

每条用户消息都要判断：哪些记忆此刻应该进入模型的感知？

生产环境里的记忆失败，常常是检索失败的伪装。
取错旧信息，比完全没有记忆更容易让模型自信地错。

07 · Trade-offs「两克伴」出品

MEMORY RISKS

记忆越强，
越要处理权衡

有用的长期记忆，也会带来过期、压缩损失和安全攻击面。

记得越久，越要判断它还靠不靠谱。
记忆不是只管写入，还要更新、衰减、验证和防污染。
