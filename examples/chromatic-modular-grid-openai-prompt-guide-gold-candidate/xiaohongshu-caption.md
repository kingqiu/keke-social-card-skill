# 小红书标题

OpenAI官方：Prompt别再套公式

# 正文

我以前做复杂任务，常常先找一条更长的 Prompt 模板：角色、步骤、格式、语气，恨不得一次写全。看完 OpenAI 这份 Prompting 指南，反而觉得第一步该做减法。

这份指南没有要求背固定结构。它提醒的是：任务变复杂时，把会改变结果的信息补进去。通常是四类：想得到什么、哪些材料影响判断、结果怎么交付、哪些事情不能擅自改。短问题不必硬塞；复杂任务也不用机械填满。

关键提醒可以按这五步看：

第一，先说结果。受众和成品格式会影响答案时，再交代清楚，别急着把过程写死。

第二，上下文要有用途。告诉它哪些文件、截图、数据源相关，以及要从里面找什么。

第三，边界只盯最贵的错误：不能改什么、缺信息要不要猜、影响别人前是否先确认。

第四，输出要能直接使用。长度、格式、读者是谁、最后要检查什么，都可以说出来。

最后，第一轮只是开始。保留已经对的部分，再具体指出下一步该改哪里，通常比整段重写更省时间。

Chat 适合快问、草稿和比较；Work 适合多来源、多步骤、需要审阅的交付；Codex 则要把目标、相关代码或复现方式、约束和验证方法讲明白。这个区分很实用：同样叫“帮我做”，不同场景需要的上下文完全不同。

我觉得最容易忽略的，是把三种任务混成一种问法。想快速理解一个问题，先把 Chat 的结果说清；要做一份会被团队使用的文件，先把 Work 的审阅标准说清；准备改代码时，先把 Codex 的复现和验证写清。这样追问时，才知道该补的是材料、边界，还是验收条件。

Prompt 的作用，是减少来回返工，让任务从一开始就有可检查的方向。评论告诉我：你现在最常让 AI 做、却最容易跑偏的任务是什么？
