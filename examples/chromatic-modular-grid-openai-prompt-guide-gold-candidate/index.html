01 / GOAL
描述结果

START WITH THE RESULT

别先写步骤，先说成品。

01
GOAL
容易跑偏

把每一步
都写死

除非过程本身很重要，否则会限制模型搜索、比较和调整做法的空间。

更有效

说清结果
和读者

要做什么、给谁看、最后长什么样，这些会直接改变输出。

结果“整理成一页项目更新”

先点明最终产物，而不是先列一串操作。

受众“给总监会前扫一眼”

受众会决定细节密度、顺序和表达方式。

格式“决策与下一步放最前”

格式是结果的一部分，不是最后才补的装饰。

→

当过程并不关键时，留出方法空间，比把每一步写死更有用。

02 / CONTEXT
补充上下文

ONLY WHAT CHANGES THE ANSWER

上下文不是堆资料，是指出关键证据。

02
CONTEXT

给来源，也告诉它
去哪里找什么。

A / FILE文档、表格、PDF

适合总结、比较、转换，或生成可审阅文件。

B / VISUAL截图、图表、示意图

点出图里关键区域，别只把图片丢过去。

C / CURRENT网页与已连接数据源

需要最新信息时要求搜索和来源；连接数据源时说明找哪里、找什么。

≠资料越多越好

无关来源会让重点变模糊，也更难核对结果。

+每份来源有用途

“从这个计划里找最新决定”，比“参考附件”更可靠。

◎跨任务偏好另放

长期偏好放个性化；只影响当前任务的细节写在 Prompt 里。

→

好的上下文不是背景介绍，而是能让答案发生变化的证据。

03 / BOUNDARIES
防住麻烦

PREVENT EXPENSIVE WRONG ACTIONS

边界只盯一两条，但要盯最贵的错。

03
BOUNDARY
01不能改什么

已批准的日期、预算、关键事实，保持不动。

02缺信息怎么办

只用给定来源；缺失就标出来，不要猜。

03影响别人前做什么

先准备草稿，发送、发布、修改前让你确认。

×

边界不是控制每一步，而是避免一次错误就让整份结果失效。

04 / OUTPUT
拿来就用

MAKE THE RESULT USABLE

好结果不是“写完”，是能直接拿来用。

04
OUTPUT
01说清它要给谁看：同事、总监、客户，还是你自己。
02说清交付形式：一页摘要、邮件、表格、文件，还是方案。
03说清长度与顺序：重点放前面，还是按时间线组织。
04重要任务再加一次终检：负责人、截止日期、无法核实的信息有没有被标出来。
USE用途决定组织

同一份信息，给会议前扫读和给执行团队跟进，结构不会一样。

CHECK让它收尾自查

先要求标出没法核实的部分，再由人决定是否使用或分享。

✓

告诉它结果准备怎么被使用，长度、细节与组织方式才会跟着对齐。

CODEX
BRIEF
01 / BEHAVIOR要什么

描述你想改变或得到的行为，不只报一个抽象问题。

02 / CONTEXT看哪里

指出相关代码、文件路径、复现步骤或附加材料。

FINAL / CHECKLIST
保存清单

BEFORE YOU SEND

复杂任务开始前，先过这一遍。

SAVE
CHECK
01
我说清了最终结果和谁来使用吗？

结果、受众或格式会改变输出时，就应该写出来。

02
我给的是会改变答案的上下文吗？

相关来源、截图、数据源要说明用途，而不是全部塞进去。

03
有没有一两条不能犯的错误？

不改什么、缺信息怎么办、影响别人前是否先确认。

04
我知道怎样验收结果吗？

格式、长度、终检条件，或可复现的验证方法。

05
第一轮后，我能具体指出改哪里吗？

保留已有证据，补一个来源、改一个方向，不必重新来过。

RULE不用每次全填

四部分不是表格，而是帮你发现“这次到底缺了什么”。

KEEP把好的 Prompt 复用

重复任务先跑通一版可审流程，再把稳定的结构留下来。

★

最好的 Prompt，不是最长的那条，而是让任务少走弯路的那条。
