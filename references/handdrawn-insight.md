# 手绘观点解读 / Handdrawn Insight

这是克克 Social Card 的补充模板，不替换任何已有模板。适用于作者文章、访谈、演讲、商业观点与阅读启发；当主要收益是一组可独立理解的观点及其应用，而非连续叙事或操作证据时优先考虑。

## 路由和调用

自然语言别名：`手绘观点解读`、`黑白橙手绘`、`像上次 PG 那套`、`作者头像观点卡`。明确指定时直接选用，不要求记住英文名。

未指定时按内容推荐；与 Longform Reader、Swiss System 等同样适合时，展示 2—3 个选项，说明各自阅读收益、信息密度和画面形式，并标出推荐项。不要只因为出现“PG”“观点”“公众号”就强制选择本模板。用户已选定的风格和参考图优先于关键词路由。

## 已确认视觉参考

- 封面：`assets/handdrawn-insight/reference-cover.png`
- 观点页：`assets/handdrawn-insight/reference-insight.png`
- 溯源：[handdrawn-insight-sources.md](handdrawn-insight-sources.md)

首次使用此模板，实际查看两张参考图。它们是用户确认的视觉基准，不是要照抄的文章、人物或观点，也未标为已通过旧 HTML 验证器的 Gold 示例。

## 视觉规则

- 3:4 竖版，白底、黑色手绘线条与排线、少量橙色强调。1080×1440 为工作目标，允许图像工具输出同等或更高的 3:4 分辨率。
- 主标题大而直接，让读者点击前知道能获得什么；允许自然分成两行。正文采用清晰的中文手写/印刷混合笔意，不用密集小字救版面。
- 人物、动作、场景共同解释观点；既不把抽象词机械画成实物，也不用空洞几何结构取代关系。现代商业、技术内容使用当代场景。
- 橙色用于关键词划线、编号、关键连接或变化，不让橙色填满背景。
- 卡片下方统一 `「两克伴」出品`，细边框与留白保持一致。封面不放大号页码；观点页可用左上角橙色编号。
- 不把迷宫、搭桥、平台、树、办公室或 PG 本人固化成默认符号。重复意象只在服务内容时使用。
- 一组内不混入 Dan Koe 黑底蚀刻封面或其他模板，除非用户明确要求比较版；比较版不混入最终发布包。

## 页面配方

页数由内容决定，不固定为九张。先保留必要观点与条件，再分配页面。

1. **封面**：读者收益标题 → 来源/范围 → 一个能表达整体主题的场景 → 简短收束与署名。
2. **观点页**：编号与结论标题 → 一句解释 → 手绘场景 → 作者观点框 → 个人解读/业务追问 → 来源与署名。
3. **对比/案例页**：用两个状态或一个具体案例作主图，保留与观点页一致的标题、作者框及底部文字系统，不必每页都画左右对比。
4. **总结页**：少量可复用问题或行动检查；标明是账号作者的整理，不能冒充来源作者的检查表；保留来源入口。

单页通常约 120—180 个中文字，按实际手机可读性调整。没有新信息的副标题、图注或双栏可以合并，不为了模板凑满模块。

## 作者头像与观点归属

- 有明确单一作者时，观点框默认左侧为该作者手绘头像与姓名，右侧放观点。获得官方/用户提供的人像参考后再生成；同一组使用同一个已确认头像参考。
- 换作者必须换人像，不能沿用 PG 或用户示例里的其他人物。无法确认形象时使用姓名版，不编造可识别肖像；多作者可用简短来源区代替单人头像。
- 逐字核对的短摘录才使用引号；改写或归纳必须标 `观点概括`。作者原话、原文归纳、账号个人理解要在底稿里分别记录。
- 下方“对 To B 的启发”“问问自己的业务”只是本次商业题材的用法，其他内容改为贴切的解读与追问。
- 真实截图、数据与原始证据不能用卡通示意冒充；证据是主体时改选 Proof Lab 等合适模板。

## 制作方式：明确的生成分支

`visualSystem: Handdrawn Insight`；`theme: ink-orange`；`renderMode: imagegen-full-card`。

这是原有固定 HTML/CSS 制作路径之外的独立分支。按已锁定的逐页文案和参考图，使用 `imagegen` 技能与内置 `image_gen` 直接生成完整卡片。不要强制套用其他 seed HTML、调用 HTML 渲染器重绘这些图片，或把整张 PNG 塞入 HTML 后宣称通过了字体/排版验证。

1. 记录原文、读者、页数、每页来源锚点、最终标题、观点归属、头像来源与已确认约束。
2. 遵守当前任务已有授权和确认。新风格首次制作通常先做封面＋一张代表内页供用户确认；已确认样图或用户要求直接全量生成时，不重复确认。
3. 后续页面沿用确认样图；人物头像单独作为身份参考。正文场景按页变化，标题系统、橙色强调、观点框和署名统一。
4. 保存每页准确文案、实际提示词、来源和生成图片；修改局部文字时保留其他已确认内容。
5. 使用 Writing Styles 的克克风格与小红书规则生成标题、正文、标签。已有标题不重新发散。评分按当前用户确认的门槛；分数为编辑自评，不代表流量或视觉系统成熟度。
6. 逐页查看：文字是否正确完整、头像是否对应、归属是否清楚、标题是否兑现、视觉是否一致、缩小后是否可读。发现错字或漏项先修，再交付。
7. 最终包只收录选定版本；工作稿和失败比较图留在工作目录，不覆盖已确认的原始文件。

## 文件和检查

本分支保留 `BRIEF.md`、`xiaohongshu-caption.md`（或选定版本）、`QA.md`、`assets/SOURCES.md`、`assets/IMAGE_REQUESTS.md`；`copy-variants.md` 仅在需要备选时提供，用户已锁定标题时记录已确认，不强制发散。

用 `deck-manifest.json` 标明 `visualSystem`、`renderMode`、选定 `captionFile` 和有序 `cards`。每页记录：`file`、`role`、`title`、`sourceAnchor`、`promptFile`、`review`。`review` 包括生成图片的 `sha256` 以及逐页人工检查结果 `textCorrect`、`attributionCorrect`、`portraitCorrect`、`readable`、`styleConsistent`（布尔值；不需要头像的页，确认不含误导性头像也可记 true）。这些结果必须来自实际看图，不得为了通过检查而填 true。

执行 `node scripts/check-handdrawn-deck.mjs <task-dir>`；常用 `npm run check:all -- <task-dir>` 也会识别此分支。检查文件、图序、比例、来源、人工审阅记录与图片哈希是否匹配；它不自动识别中文字形或评价审美。旧 HTML overflow/font-size/portrait-slot 检查对此分支不适用，不能伪造通过。
